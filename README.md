## 1. Overview

Electronic Health Records (EHR) contain sensitive clinical diagnoses, notes, and personally identifiable information (PII). In healthcare environments, clinicians, researchers, receptionists, and billing staff require varying degrees of data access. Broad access creates severe compliance and privacy risks, while blind perimeter security fails to protect patient confidentiality internally.

**MedGate Frontend** is the official zero-trust client portal and access control visualizer designed for **MedGate**. Built with React 18, Vite, and a high-contrast technical design system, it renders live demonstrations of:
- **Least-Privilege Role-Based Access Control (RBAC)** across 5 healthcare roles (`Doctor`, `Nurse`, `Receptionist`, `Researcher`, `Administrator`).
- **In-Situ Dynamic Field Redaction**: Automatically visualizes redacted fields, masked PII, and hidden clinical notes directly within the UI.
- **Cryptographic Audit Trail**: An interactive, chronological log with real-time SHA-256 hash-chain integrity verification.
- **Interactive Security Simulator**: A landing-page playground demonstrating instantaneous role-permission evaluations and redaction diffs without manual reloads.

The client consumes clinical datasets generated by **Synthea**, communicating directly with the `MedGate-Backend` Express REST API and Neon PostgreSQL relational database.

## 3. Architecture & Client Request Flow

```
[ User Interaction ] ──► Select Role in UI (Doctor, Nurse, Receptionist, Researcher, Admin)
         │
         ▼
[ AuthContext (State) ] ──► Stores active role, token, and simulated claims
         │
         ▼
[ API Client (services/api.js) ]
         │ (Injects Headers: x-user-role, x-user-id, x-user-name)
         ▼
[ MedGate-Backend Gateway ] ──► evaluateAccess() ──► Neon PostgreSQL Query
         │
         ├── [ 403 Forbidden ] ──► Render <AccessDeniedBanner />
         │
         └── [ 200 OK (Redacted) ]
                     │
                     ▼
         [ MedGate Frontend UI Layer ]
           • Patient Directory (<PatientCard /> & <PatientList />)
           • Clinical Graph View (<PatientDetailView />)
           • Visual Redaction Tags (<RedactedField />)
           • Cryptographic Trail (<AuditLogTable />)
```

## 5. Application Routes & Interactive Views

### 1. Landing Page (`/`)
- **Hero & Mission**: High-impact introduction to zero-trust access control for modern healthcare.
- **Interactive Role Simulator**: Live sandbox letting users select any role and immediately inspect redacted JSON, visibility breakdowns, and audit decisions side-by-side.
- **Pipeline Visualizer**: Step-by-step schematic of identity verification, RBAC evaluation, in-memory redaction, and SHA-256 logging.
- **Metrics Strip**: Key performance benchmarks ($<0.04\text{ ms}$ evaluation latency, $>400\text{k records/sec}$ redaction throughput).

### 2. Dashboard Overview (`/overview`)
- **Clinical Demographics**: Total Synthea patient counts, active encounters, and security decisions.
- **Live System Status**: Backend gateway health, active policy engine version, and cryptographic chain status.
- **Recent Audit Activity**: Real-time ticker of granted and denied access attempts.

### 3. Patient Directory (`/patients`)
- **Adaptive Grid Layout**: Responsive card grid (`.patient-grid`) supporting instant keyword filtering.
- **Dynamic De-Identification**: Displays patient names and contact information for clinical roles while cleanly masking PII for Researchers.

### 4. Patient Detail View (`/patients/:id`)
- **Comprehensive Clinical Profile**: Six relational sections (Demographics, Encounters, Diagnoses, Medications, Observations, Allergies, Appointments).
- **In-Situ `<RedactedField />` Tags**: Clear, technical explanation of why specific fields (such as psychiatric notes or diagnoses) are hidden from the current role.

### 5. Cryptographic Audit Trail (`/audit-log`)
- **Administrator Exclusive**: Guarded view enforcing strict role separation. Non-administrators receive an explicit `<AccessDeniedBanner />`.
- **Integrity Verification**: Real-time indicator displaying verified SHA-256 chain continuity across all stored events.
- **Interactive Chronology**: Sortable timestamps, relative time indicators (`2 mins ago`), outcome badges (`GRANTED` / `DENIED`), and full SHA-256 hashes.

### 6. Role Authentication & Session Inspector (`/login`, `/session`)
- **Quick-Switch Presets**: Instant one-click authentication for any of the 5 supported roles.
- **Session Inspector**: Deep dive into active token payload, simulated claims, and granted resource scopes.

## 8. Getting Started

### Prerequisites
- **Node.js** v18+ (tested on v20 and v22)
- **MedGate-Backend** running on `http://localhost:5000` (optional — includes fallback data for standalone preview)

### 1. Installation
```bash
# Clone the repository
git clone https://github.com/TeamShieldX/MedGate-Frontend.git
cd MedGate-Frontend

# Install dependencies
npm install
```

### 2. Environment Configuration
Create a `.env` file in the root directory (optional, defaults to cloud backend):
```env
VITE_API_URL=http://localhost:5000
```

### 3. Development Server
```bash
npm run dev
```
Open your browser at `http://localhost:3000`.

### 4. Production Build
```bash
# Compile and optimize production bundle
npm run build

# Preview production build locally
npm run preview
```
